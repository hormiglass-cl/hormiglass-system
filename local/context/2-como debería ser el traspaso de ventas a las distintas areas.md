# 1. Objetivo

Establecer un procedimiento interno, uniforme y controlado para el ingreso, validación, facturación, revisión y programación de las ventas realizadas por la empresa, asegurando trazabilidad documental y control operativo en cada etapa del proceso.

# 2. Alcance

Este procedimiento aplica a todas las ventas efectuadas por la empresa, incluyendo ventas directas, ventas sujetas a programación, ventas con retiro, despacho o instalación, y operaciones con pago total o con abono del 50%.

# 3. Tipología de venta y condición de pago

|  |  |
| --- | --- |
| **Concepto** | **Definición operativa** |
| Venta directa | Operación que puede ejecutarse de manera inmediata o en corto plazo, usualmente asociada a stock disponible, retiro por parte del cliente o despacho rápido. |
| Venta a programación | Operación que requiere coordinación previa de fabricación, reserva de materiales, transporte, instalación, cuadrilla o fecha de ejecución. |
| Pago total | El cliente paga el 100% del valor de la venta antes de la entrega, retiro, despacho o programación, salvo condición comercial excepcional autorizada. |
| Abono del 50% | El cliente paga un anticipo del 50% para formalizar la venta y habilitar su ingreso al proceso interno; el saldo restante se cobra según la condición pactada. |

# 4. Medios de pago aceptados

|  |  |
| --- | --- |
| **Medio de pago** | **Criterio de validación** |
| Efectivo | Debe registrarse en caja y respaldarse con el documento tributario correspondiente. |
| Transferencia bancaria | Debe adjuntarse comprobante y verificarse la efectiva acreditación del monto en la cuenta receptora. |
| Tarjeta de débito | Debe adjuntarse voucher o comprobante de transacción aprobada. |
| Tarjeta de crédito | Debe adjuntarse voucher o comprobante de transacción aprobada. |

# 5. Flujo corporativo del proceso

|  |  |  |  |
| --- | --- | --- | --- |
| **Ventas** | **Finanzas** | **Supervisión de Sucursal** | **Programación** |
| Cierra la venta y reúne antecedentes | Valida pago y emite documento | Revisa, aprueba o devuelve | Agenda fabricación, retiro, despacho o instalación |

Orden obligatorio del flujo: ninguna venta deberá avanzar a la siguiente etapa sin la validación formal de la etapa anterior. La secuencia de control es: Ventas → Finanzas → Supervisión de Sucursal → Programación.

# 6. Responsabilidades por área

|  |  |
| --- | --- |
| **Área** | **Responsabilidad principal** |
| Ventas | Captar, cerrar y formalizar la venta; reunir antecedentes completos y derivar la operación con información clara y verificable. |
| Finanzas | Validar el pago, emitir la boleta, factura o factura por anticipo, y registrar la operación en el sistema o planilla de control. |
| Supervisión de Sucursal | Verificar conformidad documental, comercial y operativa; aprobar el avance de la venta o devolverla con observaciones. |
| Programación | Coordinar la fecha de fabricación, retiro, despacho o instalación, de acuerdo con la disponibilidad operativa y la validación previa. |

# 7. Procedimiento operativo

## 7.1 Entrega de la venta por el área de Ventas

Una vez confirmada la compra, el Área de Ventas deberá reunir, verificar y registrar como mínimo los siguientes antecedentes antes de derivar la operación a Finanzas:

* Nombre o razón social, RUT, teléfono y correo del cliente.
* Dirección, comuna y modalidad de cumplimiento: retiro, despacho o instalación.
* Cotización aprobada y orden de compra, cuando corresponda.
* Detalle del producto o servicio, cantidad, valor neto y total.
* Tipo de venta: directa o a programación.
* Condición de pago: abono del 50% o pago total.
* Medio de pago y comprobante de respaldo, si ya fue efectuado.
* Fecha solicitada por el cliente y observaciones relevantes.

No deberán derivarse ventas incompletas, con datos ambiguos o sin respaldo suficiente para su posterior facturación y coordinación.

## 7.2 Validación y facturación por Finanzas

* Revisar la integridad de la información comercial recepcionada.
* Verificar la condición de pago y validar la acreditación del dinero recibido.
* Emitir el documento tributario correspondiente: boleta, factura o factura por anticipo.
* Registrar la operación en el sistema o planilla interna de control.
* Informar el estado financiero de la venta para su revisión posterior.

|  |  |
| --- | --- |
| **Estado posible** | **Descripción** |
| Facturada y pagada | La documentación fue emitida y el pago se encuentra íntegramente validado. |
| Facturada con abono confirmado | Se emitió el documento correspondiente y el anticipo fue acreditado. |
| Facturada con saldo pendiente | Existe documento emitido, pero queda saldo por cobrar conforme a la condición comercial. |
| Observada por falta de antecedentes | La venta no puede continuar hasta completar información faltante. |
| Observada por pago no validado | El pago informado no se encuentra debidamente acreditado. |

Regla de control: ninguna venta deberá pasar a Supervisión si no ha sido previamente revisada por Finanzas.

## 7.3 Revisión de Supervisión de Sucursal

* Comprobar que la venta esté correctamente ingresada.
* Verificar que el documento emitido coincida con la venta aprobada.
* Confirmar que la condición de pago esté regularizada o respaldada.
* Clasificar correctamente la operación como venta directa o venta a programación.
* Asegurar que existan antecedentes suficientes para coordinar la ejecución.

|  |  |
| --- | --- |
| **Resultado de revisión** | **Acción** |
| Aprobada para Programación | La venta puede ser remitida al área de Programación. |
| Aprobada para entrega directa | La venta puede avanzar a entrega o despacho inmediato, según corresponda. |
| Devuelta a Ventas | Se detectó información incompleta o inconsistente. |
| Devuelta a Finanzas | Se detectó observación documental o de validación de pago. |

La Encargada de Sucursal actuará como filtro operativo final antes del ingreso de la venta a Programación.

## 7.4 Envío al área de Programación

* Recepcionar únicamente ventas aprobadas por Supervisión.
* Revisar fecha requerida por el cliente y disponibilidad de recursos.
* Coordinar fabricación, retiro, despacho o instalación según el caso.
* Registrar la programación en el sistema o planilla de control.
* Informar la fecha comprometida a las áreas correspondientes.

Programación solo deberá agendar ventas que cuenten con validación financiera, aprobación de Supervisión y condiciones operativas suficientes para su cumplimiento.

# 8. Protocolos por tipo de venta

|  |  |  |
| --- | --- | --- |
| **Tipo de operación** | **Condición de avance** | **Regla operativa** |
| Venta directa con pago total | Pago validado al 100% y documento emitido. | Puede avanzar a entrega o coordinación inmediata. |
| Venta a programación con abono del 50% | Anticipo validado y registro del saldo pendiente. | No se programa sin abono acreditado. |
| Venta a programación con pago total | Pago total validado antes de la coordinación. | Puede programarse una vez aprobada por Supervisión. |

# 9. Criterios obligatorios para pasar a Programación

* Cliente correctamente identificado.
* Cotización aprobada y orden de compra, cuando corresponda.
* Tipo de venta definido y condición de pago clara.
* Pago validado por Finanzas y documento emitido o respaldado.
* Revisión aprobada por Supervisión.
* Información operativa suficiente para coordinar la ejecución.

# 10. Causales de devolución del proceso

|  |  |  |
| --- | --- | --- |
| **Origen** | **Destino** | **Motivo de devolución** |
| Finanzas | Ventas | Falta de RUT, datos de facturación, comprobante, montos consistentes o condición de pago clara. |
| Supervisión | Ventas | Falta dirección, comuna, modalidad de cumplimiento, fecha requerida o clasificación correcta de la venta. |
| Supervisión | Finanzas | Documento emitido incorrectamente o pago no validado de manera suficiente. |
| Programación | Supervisión | Información insuficiente para programar, falta de stock o indisponibilidad operativa. |
