*Uso interno*

1. Objetivo

Describir, de manera formal y secuencial, cómo se realiza actualmente el traspaso de una venta al área de Programación, desde el cierre comercial hasta la coordinación de despacho, entrega o instalación.

2. Alcance

Este procedimiento aplica a las ventas que, una vez cerradas por el área comercial, requieren coordinación operativa para despacho, entrega de materiales, retiro por parte del cliente o programación de instalaciones.

3. Áreas involucradas

| **Área** | **Responsabilidad actual** |
| --- | --- |
| Área de Ventas | Cierra la venta, revisa disponibilidad de stock, gestiona la emisión del documento comercial y realiza el traspaso de la información. |
| Área de Finanzas | Confirma si el pago del cliente fue recibido y se encuentra acreditado. |
| Área de Programación | Gestiona el despacho, la entrega del material, el retiro o la asignación de fecha de instalación. |

4. Definiciones operativas

4.1 Venta cerrada

Se entiende por venta cerrada aquella operación en la que el cliente ya confirmó la compra, ya sea mediante orden de compra o mediante pago directo.

4.2 Traspaso a Programación

Corresponde a la entrega formal de la información de la venta a la encargada de Programación, una vez confirmado el pago, para que gestione el despacho, la entrega o la disponibilidad de instalación.

4.3 Medios de pago utilizados actualmente

* Efectivo
* Transferencia bancaria
* Tarjeta de débito

5. Desarrollo del procedimiento actual

**El flujo vigente se ejecuta de la siguiente manera:**

Paso 1. Cierre comercial de la venta

Una vez que el cliente acepta la propuesta comercial, el área de Ventas da por cerrada la operación y reúne los antecedentes básicos para su gestión interna.

Paso 2. Revisión de stock y factibilidad de atención

Antes de formalizar completamente la venta, el área de Ventas revisa si existe stock disponible del producto solicitado. Esta verificación permite informar al cliente si la venta puede ejecutarse de forma inmediata, si procede por orden de compra o si debe quedar sujeta a coordinación operativa.

Paso 3. Información al cliente sobre disponibilidad y forma de pago

Con la revisión de stock realizada, el área de Ventas comunica al cliente la disponibilidad del producto y la modalidad con la cual puede concretarse la compra. Actualmente, las operaciones se materializan por orden de compra o por pago directo, utilizando efectivo, transferencia bancaria o tarjeta de débito.

Paso 4. Emisión del documento correspondiente

El mismo equipo de Ventas realiza la emisión del documento que corresponda para formalizar la operación y remitirlo al cliente. Dependiendo del caso, este documento puede corresponder a una boleta, factura u otro respaldo comercial aplicable.

Paso 5. Verificación del pago con Finanzas

Una vez cursada la venta, el área de Ventas consulta al encargado de Finanzas para verificar si el pago del cliente ya fue recibido y se encuentra acreditado. Esta confirmación es el control previo que permite continuar con el traspaso de la venta al área operativa.

Paso 6. Confirmación interna para continuar

Si Finanzas confirma que el pago está disponible, el área de Ventas habilita internamente la venta para su entrega a Programación. Si el pago aún no aparece acreditado, la operación se mantiene en espera hasta contar con la validación correspondiente.

Paso 7. Traspaso de la venta al área de Programación

Con el pago confirmado, el área de Ventas entrega la información de la venta a la encargada de Programación, incluyendo los antecedentes necesarios para gestionar la atención operativa del requerimiento.

Paso 8. Gestión operativa por Programación

La encargada de Programación revisa el requerimiento y define la gestión que corresponda: coordinar despacho, organizar la entrega del material, revisar si procede retiro o evaluar las fechas disponibles para instalación.

Paso 9. Confirmación de coordinación

Una vez revisada la disponibilidad operativa, se comunica la coordinación final para la atención de la venta, ya sea respecto del despacho, la entrega, el retiro o la fecha de instalación.

6. Resumen del flujo operativo actual

| **N°** | **Responsable** | **Actividad** | **Resultado esperado** |
| --- | --- | --- | --- |
| 1 | Ventas | Cierra la venta y reúne antecedentes del requerimiento. | Venta comercialmente confirmada. |
| 2 | Ventas | Revisa stock disponible y factibilidad de atención. | Información clara para responder al cliente. |
| 3 | Ventas | Informa forma de pago y emite el documento correspondiente. | Operación formalizada con respaldo. |
| 4 | Finanzas | Confirma si el pago fue recibido y acreditado. | Validación financiera de la operación. |
| 5 | Ventas | Entrega la venta a Programación una vez confirmado el pago. | Venta habilitada para gestión operativa. |
| 6 | Programación | Gestiona despacho, entrega, retiro o instalación. | Coordinación operativa definida. |

7. Controles actuales del proceso

* Revisión previa de stock antes de confirmar la atención de la venta.
* Emisión del documento comercial por parte del mismo equipo de Ventas.
* Consulta directa al encargado de Finanzas para verificar la acreditación del pago.
* Traspaso a Programación únicamente cuando existe confirmación de pago.

8. Registros y documentos asociados

| **Registro / documento** | **Uso actual dentro del proceso** |
| --- | --- |
| Cotización / acuerdo comercial | Respalda las condiciones ofrecidas y aceptadas por el cliente. |
| Orden de compra, cuando aplica | Formaliza la compra por parte del cliente bajo modalidad OC. |
| Comprobante de pago | Permite respaldar la operación y consultar su acreditación. |
| Boleta, factura u otro documento emitido | Formaliza documentalmente la venta hacia el cliente. |
| Información de Programación | Permite coordinar despacho, entrega o instalación. |

9. Observación sobre el estado actual del proceso

Actualmente, el área de Ventas concentra varias actividades dentro del flujo: revisión de stock, gestión de la forma de pago, emisión del documento comercial y coordinación del traspaso a Programación una vez confirmada la acreditación del pago por parte de Finanzas.

Este documento describe el procedimiento tal como se ejecuta hoy, sin incorporar todavía un rediseño futuro ni segregación adicional de funciones.
