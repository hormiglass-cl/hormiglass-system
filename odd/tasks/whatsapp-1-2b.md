# WhatsApp contract revision 1.2b (CRM → bot: chat.take / chat.release)

Objective: a CRM seller can take and release a WhatsApp chat from the opportunity; the CRM sends signed `chat.take` / `chat.release` events through its own outbox to the bot's `/webhook/crm-events`, shows the chat as taken only after the bot confirms, and stays in sync with `ownership.*` events from the bot.
Branch: `feat/whatsapp-webhook-receiver`. Delivery: `ask-on-risk`. Tests: `node --test tests/whatsapp-*.test.mjs` (throwaway local Postgres), `npm run lint`, `npm run lint:design`, `npm run build`. ## Specs

Sources: `~/Downloads/whatsapp-events-1.2b-bot-ready.md` (bot, 2026-11-15), docs/integrations/whatsapp-events-1.2-crm-response.md sections 4 and 7.

- **S1 Envelope (bot rules).** `POST <bot>/webhook/crm-events`, `Content-Type: application/json`, headers `X-CRM-Timestamp` (10-digit Unix seconds) and `X-CRM-Signature: v1=<lowercase hex HMAC-SHA256(secret, timestamp + "." + raw body)>`, with a secret **different** from the bot → CRM secret. Body ≤ 65,536 bytes UTF-8. Envelope keys only: `schema_version` (`1`), `protocol_revision` (`"1.2"`), `event_id` (`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`), `type`, `occurred_at` (UTC ISO with `Z`), `data`. `data` keys only: `crm_opportunity_id` (uuid), `crm_seller_id` (uuid), `ownership_version` (integer ≥ 0, `0` if the CRM never saw one).
- **S2 Outbox (CRM response §7).** "One row per event, written in the same transaction as the action that causes it." "Retries send identical bytes with a fresh `X-CRM-Timestamp` and signature." "Backoff on `503` and network errors. `400`, `401`, `409` and `422` stop the retries and are shown to the seller or an admin." Same `event_id` is only ever sent with the same bytes.
- **S3 Confirmed take (CRM response §4).** "The CRM shows the chat as taken only after the bot replies `200 applied` with `ownership_version`. On `409` it shows who holds the chat. The button never changes the state optimistically." Every event carries the `ownership_version` the CRM last saw.
- **S4 Responses.** `200 applied` → store the returned `ownership_version` and owner state; `200 ignored_stale` → nothing changes, refresh state; `409 ownership_conflict` → show holder (`holder_crm_seller_id`, may be null); `409 event_conflict`, `422 invalid_opportunity|invalid_seller`, `400 invalid_event`, `401`, `413` → stop and show; `503` / network → retry with backoff.
- **S5 Release.** `chat.release` only by the current holder; on `200 applied` the bot owns the chat again.
- **S6 Echo.** The bot echoes CRM actions back as `ownership.taken` (`source: "crm"`) / `ownership.released` (`seller_released`) with the new version; the receiver treats them as confirmation, not a new action (no duplicate notifications, no state flip).
- **S7 Config.** Bot URL and outbound secret are server-only configuration; the feature is off when either is missing. Secrets never in docs, logs or the browser.
- **S9 Who acts (user, L4).** "Vendedor asignado y admin": only the opportunity's assigned seller or an admin can take; the take is sent with the actor's own `crm_seller_id`. Release only by the current holder, or an admin on the holder's behalf (sent with the holder's `crm_seller_id`, as the bot requires the holder). Assumption: an admin take is sent as the admin.
- **S8 Docs.** Contract doc documents the CRM → bot sender; the bot gets confirmations 1 and 2 of its "What we need from you".
